# PDF 试卷切分方案调研

调研日期：2026-10-25。来源为项目维护方 GitHub README / 文档；未对下列引擎在本项目试卷上做同数据集效果评测，排序是工程选型判断，不是准确率排名。本次仅调研，没有安装新模型或向第三方上传试卷。

## 结论

优先复用现有 PaddleOCR 服务，把“整页版面检测”和“逐题公式识别”分成两个任务，再增加原生 PDF 坐标提取分支。完整题目需要包含题干、选项、公式和配图；通用版面模型给出的段落框不能直接等同于一道题。

| 方案 | 官方能力与适用点 | 对拾题的接入判断 |
| --- | --- | --- |
| [PaddleOCR / PP-StructureV3](https://github.com/PaddlePaddle/PaddleOCR) | PDF/图片结构解析，提供文字等细粒度坐标 | 第一候选：已部署其正文和公式识别依赖，扩展独立 layout 接口可降低新增依赖；需自建按题号、栏序聚合的逻辑 |
| [MinerU](https://github.com/opendatalab/MinerU) | 复杂文档解析为 Markdown/JSON | 可选高质量结构适配器；部署与模型资源须按选定版本评估，不宜直接替换 Rust 主进程。当前主仓声明为基于 Apache 2.0 且附加条件的 MinerU Open Source License，不能沿用旧版本许可证印象 |
| [DocLayout-YOLO](https://github.com/opendatalab/DocLayout-YOLO) | 文档版面检测 | 专门定位候选块的备选；不直接完成解题或题目语义聚合。主仓标示 AGPL-3.0，分发代码、模型前需核对实际依赖与许可证 |
| [Docling](https://github.com/docling-project/docling) | 版面、阅读顺序、表格、公式，支持本地执行和结构化 JSON | 通用结构接口备选，适合多格式；不是现成数学试卷拆题器。代码仓 MIT，模型许可应分别核对 |
| [MathPaperStruct](https://github.com/whuzyt/MathPaperStruct) | MinerU + DeepSeek 数学试卷结构化流水线；确定性拆题支持数字题号、中文大题标题、选项排除与答案区 | 最贴近业务，可借鉴“文档解析→规则拆题→结构化→质量审核”的分层；仓库说明不等于在中文扫描试卷上的实测保证，不能盲目把每个正则命中当边界 |

## 建议的处理链（工程设计）

1. 原件永久保存；原生文字 PDF 优先提取带页码与坐标的文字块。扫描或文本层损坏的页再进入视觉分区。PDF 点坐标、渲染像素坐标必须有明确转换。
2. 版面检测只生成块：正文、公式、选项、图表、页眉页脚、置信度、阅读顺序。先处理栏序，再处理题号，避免双栏串题。
3. 题目聚合器识别 1./1、/第1题 与大题标题，排除 A–D 选项和 (1)(2) 子问；附图按空间位置、图注与题干引用归属。同题跨页时保留多段原图 origins，而不是把页面拼成一个无法追溯的框。
4. 生成候选题区域，低置信度、题号不连续、缺选项、跨栏/跨页归属不确定的题进入人工复核。共享材料作为关联对象保留，不能强行切掉。
5. 人工确认后逐题 OCR；Agent 可辅助判断边界和编写答案解析，但所有结果必须能对照来源页与坐标。

## 接口建议（尚未实现）

独立 layout worker 输入页面图或原生 PDF 文本块，返回 `page, width, height, blocks[{bbox, category, text, confidence, reading_order}]`。Rust 校验坐标范围、版本与来源，再生成现有 RegionInput / origins。每个适配器标注 engine/version，不把整个解析引擎嵌入 Web 请求线程。

现有结构化导入接口可作为过渡；自动区域建议应作为可审核提案写入，不能直接覆盖人工已编辑题目。后续长任务应持久化 queued/running/succeeded/failed 状态、逐页检查点与可重试错误，前端轮询进度；取消应由工作进程确认终止后释放资源，不能仅靠浏览器断开请求模拟取消。

## 当前保存卡顿的修复边界

本轮修复等待队列与裁切超时、输入框禁用恢复、弹窗内进度/错误、重新载入入口和 Tesseract TSV 输出配置。裁切在 spawn_blocking 执行，不持有数据库锁；只有裁切完成且版本一致后才事务替换题目。超时后的后台裁切线程可能继续完成文件生成，但不会提交题库修改，处理许可仍由线程持有，避免提前释放后无限并发。完整持久任务队列属于后续架构改进，不能把本轮的超时措施描述成已支持后台恢复。

## 验证建议

使用同一组脱敏的单栏、双栏、跨页、含配图/共享材料试卷，比较完整题目召回、误拆/漏拆、图文归属、人工修框次数、耗时和峰值内存；不能只比较 OCR 字符准确率。本文能力描述来自官方仓库文本，未核验任何样卷公式或最终数值。
