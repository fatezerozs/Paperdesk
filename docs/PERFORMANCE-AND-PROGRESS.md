# 识别资源管理与进度

## 默认策略

- Rust 渲染、裁切、识别共享一个重任务许可，避免多个高占用任务同时执行。异步 HTTP 线程与重任务分离；Tokio 运行时使用 2 个工作线程。
- Tesseract/Poppler 子进程限制 OpenMP 线程；Windows 使用低于正常的进程优先级。
- PaddleOCR HTTP 服务与模型推理进程分离。一个模型进程处理一项推理，默认 2 个 CPU 线程（低核心数机器为 1），文字/公式识别批量均为 1。OpenMP/MKL/OpenBLAS 同步限线程，等待线程采用被动策略。Windows 优先级低于正常，Linux 使用正 nice 值。
- 设置 `PAPERDESK_OCR_THREADS` 后重启模型服务可调整线程数，最多 4，并按核心数预留余量。线程少可降低桌面干扰，但不保证单题耗时缩短。
- 默认单次推理硬超时 120 秒。版面请求根据 Rust 剩余预算使用更短期限；超时后终止模型子进程并重新加载，不让已超时推理继续阻塞后续任务。恢复期间健康接口仍响应；新推理请求返回繁忙/未就绪，而不会无限排队。
- 最近 8 个成功的相同输入结果在服务内存中缓存，重复请求可复用；重启/模型恢复后清空。不会把失败结果缓存为成功，也不会把此缓存用于外部付费 OCR。

公式模型仍较重；限线程、单批量与优先级控制能约束资源争抢，不能保证在所有硬件上消除内存压力。GPU 推理仍需要用户自行具备适用硬件与运行环境，本轮没有自动安装 GPU 依赖。

## 可视化

上层进度按已处理文件/题目计数，包括失败和跳过项，不代表成功率；错误和受保护题目数量单独显示。下层显示实际后端阶段与已完成页数/区域数。未知内部进度（如单个公式推理）使用不定进度条，不生成虚假百分比。支持后台处理：收起导入窗口后可继续使用题库，右下角返回任务。

“停止后续任务”在当前文件或题目完成后生效，不是强杀当前模型。已完成结果保留；服务超时/恢复时自动停止后续识别，剩余题目可稍后重试。后台处理仅指当前浏览器页面中继续执行；关闭页面或重启程序不提供持久任务恢复。

## 进度接口

1. `POST /api/operations`（X-Paperdesk: 1）创建记录，得到 id。
2. 上传、保存区域或识别请求附带 `X-Paperdesk-Operation: {id}`。一个记录只允许领取一次。
3. `GET /api/operations/{id}` 返回 status、phase、completed、total、unit、message。total 为 null 表示未知内部进度。

进度表在内存中有界保存 128 条，优先淘汰已结束记录及超过 5 分钟未提交的记录。重启后记录清空。兼容没有操作头的旧客户端；原 API 的结果与人工修订保护保持不变。

## 诊断

本地模型 `GET http://127.0.0.1:8850/health` 返回 ready、state、busy、threads、worker_pid、cache_hits。健康端点独立于模型推理，不应再因为某题很慢而等待整段推理。原始题目仍保留，失败项不会自动标记成功。

## 异常恢复与操作层级

- 仅有待拆分文件时显示拆分按钮；两份以上已拆分资料才显示批量识别。当前来源保留保存范围与开始识别两个不同操作，已保存且无改动时禁用保存。
- 进度区区分处理中、成功、部分完成、停止和失败。计数表示已处理数量；失败时阶段条清零并给出重试提示，不显示成功完成。
- 识别错误只显示简短操作建议，原始错误收进技术详情；重复分区提示去重后默认折叠。
- 识别失败后解除操作锁定，可重试失败与尚未处理题目，跳过已成功项；人工修订及已核验题目的原有保护保持有效。
- 后台任务报告失败时前端及时结束等待。进度接口连续三次不可达时解除等待，并说明后台结果尚未确认；重新打开来源检查结果后再重试，避免误认为后台已取消。
- 本地 Paddle 请求等待上限为 150 秒，覆盖模型默认 120 秒推理预算与恢复余量。外部 Paddle 保留 300 秒兼容期限。请求中断时进度进入失败终态，重任务许可仍由实际工作持有，避免并行启动重复重任务。

验证：Rust 任务中断/成功终态测试；浏览器故障注入验证识别错误后重试成功、后台失败及进度接口失联均解除锁定、重复操作隐藏与诊断信息折叠。

进度视觉采用细线、弱边框与紧凑状态层级：已知完成数量时平滑推进；未知推理进度使用流动条与呼吸状态点，时间以 mm:ss 实时更新。结束即停止动画，系统减少动态效果设置下关闭动画。

浏览器回归脚本位于 `tests/browser/import-recovery.cjs`。在项目根目录、已有本地服务及 Playwright/浏览器的环境执行 `node tests/browser/import-recovery.cjs`；可通过 `PAPERDESK_TEST_URL`、`PAPERDESK_PLAYWRIGHT_MODULE`、`PAPERDESK_BROWSER_PATH` 指定服务与运行依赖。脚本只拦截并修改测试接口响应，不向现有题库写入数据。
