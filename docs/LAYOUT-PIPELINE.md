# 自动分区与逐题识别

## 用户流程

导入 PDF / 图片 → 拆分并预览 → 人工核对题干、选项、配图 → 保存拆分 → 识别本份。沿用现有前端修框、坐标编辑和逐题溯源界面；自动分区不代表审核通过。

原生 PDF 优先使用本地 PDFium 提取文字坐标，转换到渲染图的像素坐标。旋转页、无有效文本层、含大幅扫描底图的页回退到视觉检测。扫描页调用本地 PaddleOCR 的页面布局接口，关闭公式转写，仅检测版面和文字行。之后由 Rust 按栏序、题号与图表位置聚合为题目区域，逐题裁切并保留原页。最终题干、公式和答案解析在后续识别/Agent 阶段生成。

## 模块与接口

- `src/layout.rs`：本地服务适配器、尺寸/坐标验证、题目聚合与质量提示。
- `src/importer.rs`：原件存储、渲染、裁切、确认与事务写入。
- `services/math-ocr/server.py`：`POST /pdf-layout` 原生 PDF 坐标、`POST /page-layout` 整页布局、原有 `POST /layout-parsing` 逐题正文与公式识别。
- `ImportPlan.regions_confirmed`：图片候选是否人工保存确认；未确认时后端拒绝逐题识别。旧记录缺少此字段时默认为 false，需在预览中确认。
- `ImportPlan.layout_reports`：每页使用的引擎、块/行数量、复核要求。完整坐标结果存于来源目录的 `layout-{page}.json`，不覆盖原件。

服务返回像素坐标 `bbox: [left, top, right, bottom]`，页面宽高须与预览一致。文字行包含 text、confidence（未知为 null）、order，版面块包含 category。未知置信度不能解释为已核验。Rust 限制结果体积、块数量与坐标范围。

## 配置与失败处理

工作区设置中的本地 PaddleOCR 地址为 `http://127.0.0.1:8850/layout-parsing`，同一配套服务派生另外两个接口。启动脚本与模型部署方式不变；服务升级后须重启。新增显式依赖 pypdfium2。仅回环地址的配套服务参与整页/整份 PDF 分析，不会将完整 PDF 发给 Mathpix 或自定义在线 OCR。

本地服务不可用、接口版本不支持或超时时，明确提示并回退到 Tesseract TSV 题号检测；没有可靠边界则保留整页/整栏候选。整个准备阶段有时间预算，不会逐页无限等待模型。手动版面模式不调用自动布局。

保存拆分后会标记确认；新生成的自动候选仍处于 pending。已人工编辑/审核的题目保持覆盖保护。旧客户端非 staged、未开启公式增强的文字 PDF 导入仍保留兼容文字路径，GUI 始终使用 staged 流程。

## 保守处理边界

A–D 选项、(1)(2) 子问不作为大题锚点。题号跳跃、答案区、疑似跨页续题、跨栏图表和穿过公式/图片的边界会提示人工处理。跨页题目不会在缺乏可靠证据时自动合并；当前修框界面仍以每页区域为单位，自动跨页合并和共享材料归属不是本轮已完成功能。原生 PDF 的矢量题图也仍需人工检查。

本轮保留请求式接口与阻塞工作池，增加分阶段预算与失败回退；尚未实现持久任务队列、断电续跑或硬终止模型推理。超时不会自动重试付费服务。
